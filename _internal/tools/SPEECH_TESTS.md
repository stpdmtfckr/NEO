# Проверка речи NEO на вашем компьютере

Обычная сборка сохраняет faster-whisper: tiny для активации и выбранную модель для команд. Ollama не участвует в распознавании речи. Тест ниже **не запускает команды**, не открывает приложения и не отправляет звук в интернет.

## Записанный корпус

Создайте короткие PCM WAV: отдельное «Jarvis», «Jarvis, открой папку», короткие команды, названия файлов/треков, разговор без обращения к ассистенту. Добавьте записи в тишине, с музыкой из колонок и с шумом. Для семи языков используйте настоящую речь носителей или пользователей, а не только синтетический голос. Каждый файл — до 120 секунд.

Рядом с WAV создайте `corpus.json`:

```json
[
  {"file": "wake_ru.wav", "purpose": "wake", "language": "ru", "wake": true},
  {"file": "background.wav", "purpose": "wake", "language": "ru", "wake": false},
  {"file": "folder_de.wav", "language": "de", "expected": "öffne den ordner"},
  {"file": "music_es.wav", "language": "es", "expected": "pausa la música"}
]
```

Из `_internal` выполните установленным Python приложения:

```text
python tools/verify_speech.py --corpus corpus.json --model C:\path\to\small-model --wake-model C:\path\to\tiny-model --repeat 3 --output speech_report.json
```

Пути `--model` и `--wake-model` должны указывать на уже установленные каталоги с `model.bin`. Диагностика сама модели не загружает. Результат содержит точность, WER, принятие/отклонение wake и задержку ASR. Первый вызов включает холодную загрузку модели. Записанные файлы и текст отчёта могут содержать личные данные: выбирайте самостоятельно, какие записи передавать для разбора.

## Что этот тест не доказывает

WAV-тест не измеряет задержку живого микрофона, драйвера, VAD, UI или исполнения команды. Для этого запускайте приложение и сопоставляйте DEBUG-строки `ASR request/result` по `correlation_id`; они не содержат записанного аудио или текста команды. CPU/GPU и игровую производительность сравнивайте на одном ПК с одинаковыми устройствами и настройками, отдельно при скрытом окне, музыке и игре. Текстовые тесты `test_wake.py` проверяют матчинг, но не акустическое качество.

Экспериментальный акустический detector по умолчанию выключен. При явном включении используется только уже установленная локальная модель openWakeWord, с отдельным процессом и откатом к Whisper при ошибке. Стабильность ONNX и точность требуют проверки на Windows.
